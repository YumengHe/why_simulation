3. Reading a URDF file

A URDF file tells us what the parts are, what they look like, and how they connect. Let’s read one using the cabinet we already know.

3.1 One file, parts and connections

The whole model sits inside <robot>. Inside it, <link> describes a part, and <joint> connects two parts. The word “robot” is simply the format’s name for the whole model; this one is a cabinet.

A pair such as <link> … </link> marks the beginning and end of a block. A tag ending in /> is complete on its own.

The file’s outline

<robot name="cabinet">
  <link name="base" />
  <link name="link_2"> … </link>
  <link name="link_0"> … </link>
  <link name="link_1"> … </link>

  <joint name="joint_2"
         type="fixed"> … </joint>
  <joint name="joint_0"
         type="prismatic"> … </joint>
  <joint name="joint_1"
         type="revolute"> … </joint>
</robot>

This outline leaves out the details. Each … stands for lines inside that block.

The connections it describes

baseReference link · no shape
joint_2 · fixed↓
Cabinet bodylink_2
joint_0 · slides↓
Drawerlink_0
joint_1 · rotates↓
Doorlink_1

The file lists the parts; the joints make the tree. The drawer’s link is not written inside the body’s link. A joint connects them by naming one as its parent and the other as its child.

Names such as link_0 are identifiers. Here they mean “drawer”; another model could use drawer directly. What matters is using the same name when referring to that part.

3.2 Link: shapes that move together

The drawer’s sides, bottom, front, and handle all move together, so they belong to one link. A link can contain several <visual> blocks, each describing a shape to draw.

Reading one visual block

This excerpt describes the red top strip in the picture. Positions are rounded here to make the code easier to read.

<link name="link_0">
  <visual name="drawer_front-14">
    <origin xyz="0.0142 -0.5376 -0.4921" />
    <geometry>
      <mesh filename="textured_objs/original-34.obj" />
    </geometry>
  </visual>
  <!-- The other drawer shapes go here too. -->
</link>
link
The whole drawer. All shapes inside this link follow the drawer’s motion.
visual
One visible shape belonging to that drawer.
origin
Places this shape relative to the drawer’s own zero point.
geometry
mesh
Describes the shape. Here, mesh tells the viewer which 3D shape file to open.

<geometry> can also contain a simple <box>, <cylinder>, or <sphere>. A separate mesh file is not required for every shape.

This drawer has 14 visual blocks but only one sliding joint. More shape files do not mean more degrees of freedom.

3.3 Joint: let the drawer slide

A <joint> answers a different question: how can this part move relative to the part it is attached to? Here the body is the parent, and the drawer is the child.

<joint name="joint_0" type="prismatic">
  <parent link="link_2" />
  <child link="link_0" />
  <origin xyz="-0.0142 0.5376 0.4921" />
  <axis xyz="0 0 1" />
  <limit lower="0" upper="0.76" />
</joint>
type
Prismatic means sliding. The drawer moves along a straight line.
parent
child
Connect the body (link_2) to the drawer (link_0).
origin
Locates the joint’s starting frame relative to the body. The red dot marks the drawer’s starting point when closed, called J in the previous chapter.
axis
0 0 1 means the joint’s positive Z direction. For this drawer, that points outward.
limit
The allowed travel is 0 to 0.76 meters: from closed to 76 cm open.

One degree of freedom, one number

The drawer’s sliding joint has one degree of freedom: it lets the drawer move in and out. One number is enough to describe its position. We call that number q, the distance the drawer has opened.

  • q = 0 cm: the drawer is closed.
  • q = 30 cm: it is partly open.
  • q = 76 cm: it is fully open in this model.

The limit sets the allowed range, 0–76 cm. The value of q tells us where the drawer is right now within that range.

3.4 Joint: let the door rotate

The door uses the same structure, with a different motion type. Revolute means a hinge with a limited angle.

<joint name="joint_1" type="revolute">
  <parent link="link_2" />
  <child link="link_1" />
  <origin xyz="-0.3577 -0.5906 0.4916" />
  <axis xyz="0 -1 0" />
  <limit lower="0" upper="1.5708" />
</joint>

The origin places the joint’s starting point at the hinge. The axis gives the direction of the hinge line through that point. Here 0 -1 0 points downward in the joint’s frame.

Rotating joints use radians in the file: 1.5708 radians is approximately 90°. So this door is allowed to open from 0° to 90°. The picture shows it at that upper limit.

This hinge also has one degree of freedom. For the door, q is the opening angle; for the drawer, q is the opening distance.

A wheel that can keep turning without an angular stop would use type="continuous" instead. It has a rotation axis but no lower or upper position limit.

3.5 How a part looks and behaves

A link can describe three things about a part, such as this cabinet body:

visual
The shape you see. Draws the cabinet body and the shelf inside it.
collision
The shape used to check contact. For example, it tells the simulator whether a box touches the shelf.
inertial
How heavy the part is and how its mass is spread out. Helps calculate how it responds to pushes and turns.

This cabinet file includes visual and collision data. It has no inertial blocks, so it does not specify how heavy the parts are.

3.6 Why is there an extra base link?

Our cabinet has three visible parts, yet the file has four links. The extra one is base, an invisible reference for the whole cabinet. The fixed joint joint_2 places the cabinet body relative to that reference.

<link name="base" />

<joint name="joint_2" type="fixed">
  <parent link="base" />
  <child link="link_2" />
  <origin xyz="0 0 0"
          rpy="1.5708 0 -1.5708" />
</joint>

A fixed joint can set an orientation

The rpy numbers store a rotation. In this example, that rotation turns the cabinet body into the intended orientation. Fixed means the body keeps that orientation relative to the base. There is no extra movement to control.

Can we leave out the base and fixed joint?

Yes, with two steps: remove both elements so the cabinet body becomes the root, then apply the original fixed joint’s rotation to the whole cabinet when placing it in the scene. The drawer and door can then move exactly as before.

Keeping base and joint_2 stores the rotation inside the URDF. Removing both moves that responsibility to how we place the model in the scene.

What if we remove only the fixed joint?

The base link would be left disconnected from the cabinet. We would have two separate roots: base and the cabinet body. A URDF needs one connected tree, so a standard URDF loader rejects this arrangement. None of the three pictures shows this disconnected case.

The fixed joint adds zero degrees of freedom. With the cabinet held still, the drawer and door still provide two independent movements: one slide and one rotation.
