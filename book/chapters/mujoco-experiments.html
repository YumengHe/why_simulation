4.3 MuJoCo experiments

The model from Section 4.2 describes the cabinet. A test script loads it, applies a chosen force, and asks MuJoCo to calculate the motion. Those calculated positions can then be rendered as a video.

4.3.1 Set up the experiment

One practical setup uses MuJoCo with a Python test script on a computer:

  • The model file describes the cabinet: its parts, joints, collision shapes, mass, and resistance.
  • The Python script sets up the test: load the model, start the drawer closed and still, apply the chosen pulling force for a set duration, and ask MuJoCo to advance the simulation.
  • MuJoCo calculates the motion: the script can record opening distance and speed, while a viewer window displays the cabinet moving.

For a mass comparison, load the 2 kg version and run the pull. Then load the 4 kg version and repeat from the same starting state, keeping the force, geometry, and resistance settings unchanged. The two runs show how the assumed mass affects the result. MuJoCo’s Python interface and viewer.

4.3.2 Calculate the drawer’s motion

For a simple experiment, start with the drawer closed and still. Apply an outward 3 N force for 0.5 seconds, then remove that force. A newton (N) measures force. Continue the simulation until 2 seconds of simulated time to observe what happens after the pull ends. These are example settings for the experiment.

MuJoCo calculates the motion in small time steps. At each step, the drawer has an opening distance and a speed; together, these describe its state. “Current” and “next” refer to the same drawer at two nearby times, not simply to “closed” and “open.”

{{diagram:mujoco-experiments-flow-1}}

Ending the pull does not end the simulation. After 0.5 seconds, the applied pulling force is zero, but the drawer may still be moving. Later steps calculate whether it slows down, stops, or reaches its joint limit.

The experiment chooses when to stop stepping. Here it stops at 2 seconds, even if the drawer is still moving. Another test could stop when a target opening is reached, with a time limit if it never gets there. MuJoCo’s simulation loop.

4.3.3 Record opening distance over time

At each step, we can record the time, the drawer’s opening distance q, and its speed. Together, these records describe its motion over time: how far it opened during the pull and what happened after release. Section 4.1 shows calculated drawer examples.

The allowed range, such as 0–50 cm, is an input specified by the joint. The actual opening at each moment is a result of the simulation. A 50 cm limit does not mean this pull will open the drawer by 50 cm.

These calculated positions are the input to Section 4.3.4: the renderer draws the cabinet at each saved position to make the frames of a video.

4.3.4 Turn the calculated positions into images

Section 4.3.3 gives opening distances over time. To make a video frame, place the visible drawer at the position calculated for that frame’s time. A renderer uses those shapes, their appearance, lighting, and a camera to make a 2D frame. Save a sequence of frames to make a video. MuJoCo has its own renderer, so a separate rendering application is not required. MuJoCo rendering.

{{diagram:mujoco-experiments-flow-2}}

Changing only the camera makes a different picture of the same state. Changing the pull, mass, or friction can change the movement itself. This is why rendering and physics occupy different places in the workflow.

Where all the names fit

{{diagram:mujoco-experiments-flow-3}}

The preparation between a generated mesh and a simulation is real work; a file conversion alone does not complete it.

With NeRF or 3DGS, the beginning changes: photos → fit a scene → render new views already gives a visual result. To simulate a moving drawer, add the same physical structure described here. Keeping its learned appearance on moving parts requires an additional way to associate and move that appearance with each part.

Finally, check the test: does the drawer follow the rail, stay attached, and stop near its limit? Are there unintended overlaps? If we have a real cabinet, compare the same pull in both. When they disagree, revisit the geometry or physical settings instead of judging the simulation only by how good its video looks.
