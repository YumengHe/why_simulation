Why Simulation?

    3D software: Blender, Maya, and MeshLab

    3D software lets us create and edit models, make camera images, and work with movement. The mesh is the shape data; the application provides tools for working with it.

    Blender

    Blender is a free, open-source application for creating 3D content. We can build and edit meshes, add materials and lights, animate objects, run physics simulations, and render camera images. For a cabinet, it can handle everything from shaping the drawer to making a video of its movement.

    Maya

    Autodesk Maya is a 3D creation application with tools for modeling, rigging, animation, rendering, and simulation. We can use it to build a cabinet, set up controls for its moving parts, and produce images or animation. The rigging, keyframe, and animation-curve tools illustrated below are available in both Maya and Blender.

    MeshLab

    MeshLab focuses on inspecting and processing triangle meshes. We can use it to clean up a reconstructed cabinet, remove stray fragments, and reduce the number of faces. After simplifying a model, check that the handle keeps its shape and the opening behind it remains clear.

    MeshLab’s role here is to prepare the geometry. For the rigging and keyframe animation shown below, we use Blender or Maya. A mesh cleaned in MeshLab can be exported and opened in either application.

    The following examples illustrate modeling and rendering, animation, and physics simulation. The screenshots identify the application used; the animation diagrams explain concepts shared by Blender and Maya.

    Modeling and rendering

    First, build the object’s shape and make a picture of it. The screenshots in this example use Blender. Maya also provides mesh editing, materials, lights, cameras, and rendering; its interface looks different.

    Example: from a portrait mesh to a picture

    These Blender screenshots follow a portrait model. The mesh gives it shape, a virtual camera chooses the view, and rendering produces a picture using that view, the materials, and the lighting.

    1. Build and inspect the mesh

    The gray model is made of small, flat faces. Together, they form the head, hat, and other parts. The colored rectangle is a 2D reference image used as a guide while modeling.

    We can move around the model in Blender’s 3D viewport—the editing area—to inspect its shape. A reference picture helps with modeling; it is not the camera or the finished render. Blender’s reference-image guide explains this setup.

    2. Choose the virtual camera’s view

    Think of placing a camera in front of a sculpture. In Blender, we position a virtual camera, aim it at the model, and choose how much of the scene fits in the frame. This camera defines the view used for the final image.

    The yellow wireframe below is the camera object in the scene. Each row pairs a camera setup with a preview of the model from that viewpoint.

    A different viewpoint reveals different parts of the same model. We can choose another camera view without rebuilding the mesh. The grid and black guide lines in these previews are Blender overlays, not part of the portrait.

    3. Render the surface appearance

    With the camera set, the renderer calculates the output image. Blender displays it in the Render Result window.

    The editing view and the render above are cropped from the same screenshot. Moving around the editor lets us inspect the object; changing the render camera changes the viewpoint of the output image.

    The mesh supplies the shape. Materials give surfaces their appearance, such as a blue hat or a shiny earring. Lighting affects the bright areas and shadows.

    Rendering calculates the pixels of the camera image. The result is a 2D picture that we can save and share. The editable 3D model remains in the scene, ready to be viewed from another camera angle.

    For our cabinet, we could import a mesh, look around it, and check whether the handle is a real raised shape. If the handle or drawer tray is missing, we can build it. We can also separate the drawer and door into objects that can be moved independently.

    To make a picture, we place a camera and lights and choose a renderer. Blender includes Eevee and Cycles. They calculate images using the model’s surfaces and materials.

    Useful starting points: modeling, materials, and rendering.

    Animation in Blender and Maya

    Blender and Maya provide the rigging, keyframe, and animation-curve tools used in these examples. MeshLab is a tool for processing meshes. It does not offer the rigging and keyframe animation tools used below.

    Consider an animated arm reaching toward our cabinet, followed by the drawer opening. We first set up controls for the parts, then choose their positions over time. The diagrams illustrate the ideas rather than either application’s interface.

    1. Rigging: set up how the parts move

    The arm’s shape is already modeled. Now we tell the software where its parts can turn and which pieces should move together. We place joints at the shoulder, elbow, and wrist, then connect the visible arm pieces to those joints. We can also add a control that the animator can select and move.

    This preparation is called rigging. The resulting controls and connections form the rig. Using those controls to arrange the arm is called posing.

    The picture shows the rig being used after setup. Move the hand control toward the cabinet handle, and the software turns the connected arm joints to reach that position. This is inverse kinematics (IK). It works within the arm’s reach and the rig’s settings; we can also control which way the elbow bends. See Blender’s IK constraint or Maya’s mechanical-arm example.

    For a character with a flexible surface, skinning connects the mesh to the skeleton so the surface bends with it. A rigid cabinet drawer can simply move as one piece.

    The cabinet needs a simpler setup than this arm: one control can slide the whole drawer, and another can rotate the door around its hinge. It does not need a human-shaped skeleton.

    2. Keyframes: choose when the drawer opens

    A keyframe records a value at a chosen time. Set the drawer’s opening to 0 cm at 0 seconds and 40 cm at 2 seconds. Either application can calculate the positions between those keys. With constant speed, the drawer is 20 cm open after 1 second.

    3. Graph Editor: adjust how the movement feels

    The Graph Editor displays values over time. Here, the horizontal axis is time and the vertical axis is drawer opening. A straight line gives constant speed. A curve that starts and ends gently makes the drawer speed up and then slow down. We can edit the curve while keeping the same start and end positions. Both Blender and Maya provide a Graph Editor.

    These tools let us design a movement. Changing the curve changes the positions the animation follows. Calculating motion from gravity, a pull, or a collision requires a physics setup.

    Physics simulation: a box falls onto a shelf

    Open the lower door of the same cabinet, place a small box above its bottom shelf, and let go. We want gravity to make it fall and contact with the shelf to stop it. Blender and Maya can both run this kind of rigid-body simulation, in which the objects move without changing shape.

    The example below was calculated in Blender using its rigid-body physics system. The cabinet and box were built by a script, and a fixed camera rendered the calculated positions.

    1. Prepare the objects. Give the movable box a mass of 1 kg and a box-shaped collision boundary. Give the cabinet walls and shelf fixed collision shapes.
    2. Set the starting conditions. Start the box at rest above the shelf and enable gravity. No keyframes tell it where to go or when to stop.
    3. Run the physics calculation. The simulator updates the box’s motion over time. Contact with the shelf prevents it from passing through.
    4. Render the result. The camera makes pictures of those computed positions using the scene’s materials and lighting.

    The last two positions are simulation outputs. We supplied the starting pose, gravity, and physical settings. With gravity off, this box would remain at rest in the air; without the shelf’s collision shape, it would fall through the visible shelf.

    Where are these settings in each application?

    In Blender, use the Rigid Body physics settings: an Active box is moved by the simulation, while Passive cabinet parts stay fixed in this example. In Maya, the Bullet plug-in provides rigid bodies and a solver to calculate their motion. The commands differ, but both need the objects, collision shapes, and physical settings. See Blender’s rigid-body introduction and Maya’s Bullet guide.

    A rig control sets a pose for animation. A force, such as gravity, changes motion through a physics calculation. Both can be used within either application. For the drawer’s pulling-force examples, see From animation to simulation.

    A cabinet workflow

    1. Open the model. Import an existing cabinet mesh or create its parts in the editor.
    2. Inspect and edit. Check the size, orientation, drawer interior, and handle opening. Repair missing geometry and keep parts that should move separately.
    3. Choose the output. Render an image to show how it looks, or export the part meshes to use in an articulated model.

    Exported meshes describe the shapes. The URDF model describes their connections and allowed motion. A simulation model also needs contact shapes and physical properties.

    These applications are alternatives for preparing geometry; a cabinet does not need to pass through all three.
