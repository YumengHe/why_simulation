# Why Simulation?

A webbook that connects AI instructions and actions to 3D objects and simulated motion.

The opening **Overview** page contains contribution links, contacts for Yumeng He and Chenfanfu Jiang, and ArticulateArena's complete citation with copyable BibTeX. Version and Community Contributors are intentionally blank.

The book has three main sections:

1. **Text-only LLM → VLM → VLA** introduces language, vision, and robot actions through a drawer-opening example, then explains why an action needs to be tested in a modeled world.
2. **3D generation** introduces creating assets, point clouds, triangle and quad meshes, rendering tools, and 3D Gaussian Splatting. It includes cabinet projection videos and interactive opacity comparisons.
3. **Articulated objects** contains all five existing chapters: parts and joints (3.1), frames and URDF (3.2), reading a URDF (3.3), changing a URDF (3.4), and animation and simulation (3.5). Existing chapter URLs and section anchors remain valid.

The sidebar lists chapters and the section names within Chapter 2. Detailed topics remain expanded in the chapters and searchable through the book search. New representation diagrams are original schematic SVGs, not generated or reconstructed benchmark results.

Section 2 follows images into 3D geometry and appearance, then explains how rendering turns a stored 3D scene into a new image. Its worked examples cover mesh rendering, Gaussian projection, and front-to-back opacity blending. The chapter names tools such as Blender and gsplat and explains the custom Python renderer used for the teaching videos. Both the single-pixel and whole-cabinet opacity demonstrations remain expanded. Regenerate the original figures with `python3 scripts/draw_representation_diagrams.py` and `python3 scripts/draw_reconstruction_story.py`, then rebuild the book. These diagrams are teaching examples, not trained reconstruction results.

Section 1.3 uses a static flow diagram to connect a camera image and instruction to a VLA, a concrete movement/gripper command, the controller, and the next image. Every step stays visible. The illustrated commands are teaching examples, not predictions recorded from a trained VLA. The before/after SVGs are original schematic drawings generated by `scripts/draw_vla_flow.py`; their two-link arm uses inverse kinematics only for drawing. The example distinguishes predicting an action from simulating the physical response.

## Preview locally

Requires Python 3.10 or newer; no packages need to be installed.

```sh
python3 scripts/build_book.py
python3 scripts/serve_book.py --port 8769
```

Open [the Overview](http://127.0.0.1:8769/overview.html). The root URL still opens the original articulated-object introduction for compatibility.

## Edit the book

| Location | Purpose |
| --- | --- |
| `book/book.json` | Book title, chapter order, and page names |
| `book/chapters/` | Chapter content as HTML fragments |
| `book/layout.html` | Shared toolbar, contents, search, and footer |
| `book/assets/` | Styles, interactions, fonts, and cabinet media |
| `scripts/build_book.py` | Dependency-free static builder |
| `docs/` | Generated website, ready for GitHub Pages |

Edit the source in `book/`, then rebuild. Keep chapter output files at the root of `docs/` so all pages share the same relative asset paths.

To add a chapter, create an HTML fragment in `book/chapters/` and add its `number`, `title`, `source`, and `output` to `book/book.json`. Omit `number` for an unnumbered page such as Overview. The book-title links open the first configured page. Use `<header id="chapter-start">` for the chapter heading and `<section id="unique-anchor" data-title="Section name">` with an `<h2>` for each section. The builder generates navigation, search entries, and previous/next page links from those files. Add a `group` key to place consecutive pages inside a group declared in `groups`; headings within a page are indexed for search but do not appear in the sidebar.

The reading controls support a collapsible table of contents, `/` to search, Escape to close search or the mobile menu, and chapter printing. Animations respect reduced-motion preferences. The examples run entirely in the browser.

Figures in the URDF chapter open in an enlarged view without leaving the page. Close that view with its Close button or Escape. All chapter explanations remain expanded in the normal reading layout.

Section 3.5 uses an original browser demonstration in `book/assets/physics-demo.js`: one-dimensional motion integrated with semi-implicit Euler at 240 steps per second, with a static tabletop and perfectly inelastic contact. There is no air resistance, bounce, or rotational motion. The comparison autoplays; reduced-motion preferences show settled results instead. The demo uses no external physics engine. Optional per-chapter JavaScript files are listed under `scripts` in `book/book.json`.

The same chapter adds four original paired drawer GIFs: different pulls, different masses, different rail friction, and motion after release. `scripts/animate_drawer_forces.py` calculates one-dimensional dynamics from illustrative properties, then draws side views. It uses exact constant-acceleration updates over 1 ms segments, resolves stopping under Coulomb friction, and includes inelastic travel stops at 0 and 0.76 m. Static friction balances forces up to its threshold; it is not always equal to that threshold. The geometry is a teaching diagram, not measured cabinet geometry. This model does not run a full 3D contact simulation.

Regenerate the force examples with `python3 scripts/animate_drawer_forces.py` after installing the optional animation dependencies below. Run `python3 scripts/animate_drawer_forces.py --check` to check independent analytic results for acceleration, coasting, stopping distance, sticking, and travel limits. Numerical traces and settings are saved in `book/assets/forces/manifest.json`. Wide and stacked GIFs keep each comparison synchronized on desktop and mobile; PNG end states support reduced motion and printing. Playback is half speed, with holds at the first and last frame before the experiment resets.

Section 3.4 GIFs autoplay and loop. Static endpoint images replace them for reduced-motion preferences and printing, including in the enlarged view. To regenerate these assets, install the optional authoring dependencies and run:

```sh
python3 -m pip install -r scripts/requirements-animation.txt
python3 scripts/animate_urdf_examples.py
python3 scripts/build_book.py
```

The animation generator checks the changed axes, travel distances, closed-pose alignment after swapping shapes, and the unchanged door motion after removing the drawer. Run only those checks with `python3 scripts/animate_urdf_examples.py --check`. It uses the checked-in geometry snapshot, fixed cameras, and a shared color palette per GIF. The six axis/type examples label the joint's zero-pose reference frame: +X red, +Y green, +Z blue, with the chosen motion axis in purple. These arrows use the same camera projection as the geometry. In this asset the moving joints have zero origin RPY, so their reference directions match the cabinet body frame (+Y up, +Z out of the front); they are not the world-axis convention introduced in Section 3.2. The translucent cabinet reveals the motion; the renderer does not simulate contact or gravity.

## Hosting

The generated website is in `docs/`. To host it with GitHub Pages, configure deployment from the `main` branch and `/docs` folder. All assets use relative paths so the book can be hosted under `/why_simulation/` or a custom domain.

## Sources

- Section 2.4 projection video is an original 52-second teaching animation. `scripts/animate_projection.py` separates the external diagram viewpoint from the illustrated pinhole camera: the diagram rotates at 0:16, the image plane is viewed face-on at 0:26, and the camera moves around fixed blobs from 0:36. Projected Gaussian covariances use the perspective Jacobian and colors use depth-sorted alpha blending, following the [gsplat formulation](https://docs.gsplat.studio/main/apis/rasterization.html). The ellipsoid outlines indicate one standard-deviation shape guides, not hard Gaussian boundaries. This is an illustrative scene, not a trained reconstruction. Regenerate with the optional animation dependencies and `python3 scripts/animate_projection.py --ffmpeg /path/to/ffmpeg`; use `--check` for analytic checks or `--stills` for the five key frames. The virtual image plane is in front of the camera; it is not a physical camera sensor. Video playback is user-controlled and does not autoplay or loop.
- Section 2.4 also includes a separate original 64-second cabinet video from `scripts/animate_gaussian_cabinet.py`. Its 2,146 fixed, surface-aligned Gaussians form a simple cabinet; the film enlarges one thin blob, projects the cabinet onto a virtual image plane, then moves the camera while all Gaussians remain fixed. The same perspective covariance projection and depth-sorted alpha blending generate the image-plane texture and camera view. Outlines are shape guides, not hard boundaries. This is an analytic teaching scene, not a trained reconstruction. Use `--check`, `--stills`, or `--ffmpeg /path/to/ffmpeg` as with the two-blob video. Both videos remain available with independent chapter controls. The opacity illustration updates together with its slider and calculated pixel.
- The cabinet opacity comparison re-renders that same scene at 0–100% peak opacity per Gaussian in 5-point steps. All centers, covariances, colors, and the camera remain fixed. `scripts/draw_cabinet_opacity.py` generates 21 lossless WebP views; the slider swaps those rendered views beside a fixed 95% reference. These are individual Gaussian opacities, not a whole-object transparency percentage. The original pixel demonstration and both videos remain intact.
- Section 2.1 toolbox input and matched output views: [TRELLIS image-to-3D gallery](https://microsoft.github.io/TRELLIS/), credited to the authors. These are actual published results, not locally generated reconstructions. See `book/assets/examples/trellis-toolbox/SOURCE.md` for original asset links and the source's academic/research-use restriction.
- Cabinet media and adapted teaching examples: [ArticulateArena website](https://github.com/YumengHe/ArticulateArena-web), MIT license, copyright 2026 Yumeng He.
- Cabinet origin diagram: projected from the [45168 example geometry](https://github.com/YumengHe/ArticulateArena/tree/11e49256b8e839f04e5da2f481cbea20c54bc2ce/sample_data/45168) in ArticulateArena, following the O/J explanation in the supplied AIVC notes. It shows the drawer at its zero position in the body link's frame.
- URDF chapter figures: original SVG projections of the 45168 geometry, following the examples on pages 14, 18, 25, and 26 of the user-supplied `AIVC.pdf`. Labels and captions are rewritten for beginners. `scripts/data/cabinet-45168.json` stores the source geometry and joint transforms; `python3 scripts/draw_urdf_figures.py` regenerates the five SVGs in `book/assets/figures/`. The drawer is shown at q = 76 cm and the door at q = 90 degrees, their upper position limits. The fixed-joint comparison uses the actual joint_2 rotation and the same Z-up scene/camera in all three panels. Keeping that joint or applying its transform to a new body root gives the same pose; deleting it without replacement does not.
- Section 3.4 animations follow the examples in the six-page user-supplied `AIVC (1).pdf`: drawer axis changes (pages 2–4), swapping geometry and removing the drawer (page 5), and changing the door from revolute to prismatic (pages 5–6). No PDF images or evaluation scores are embedded. The diagonal axis is normalized to unit length. Swapped shapes preserve their original closed placement before following their new joints; the offset cancellation used by the renderer applies to this model's saved coordinates and zero joint rotations, not to every URDF.
- URDF structure and terminology: [ROS-Industrial URDF introduction](https://ros-industrial.github.io/ros2_i_training/_source/urdf/introduction.html). Section 3.3 shows shortened excerpts from the model, with rounded numbers; they are not advertised as a complete simulator-ready model.
- Section 3.5 physics explanations: OpenStax University Physics Volume 1, [Newton’s first law](https://openstax.org/books/university-physics-volume-1/pages/5-2-newtons-first-law), [Newton’s second law](https://openstax.org/books/university-physics-volume-1/pages/5-3-newtons-second-law), and [friction](https://openstax.org/books/university-physics-volume-1/pages/6-2-friction). The drawings and simulations are original; source figures are not copied.
- New introductory pages cite the original [Llama 2](https://arxiv.org/abs/2307.09288), [LLaVA](https://llava-vl.github.io/), [OpenVLA](https://openvla.github.io/), [TRELLIS](https://microsoft.github.io/TRELLIS/), [NeRF](https://www.matthewtancik.com/nerf), and [3DGS](https://repo-sam.inria.fr/fungraph/3d-gaussian-splatting/) sources, alongside the Open3D and Blender documentation. Their drawer conversations and representation drawings are teaching examples.
- Book layout reference: [Physics-Based Simulation](https://phys-sim-book.github.io/). The layout is independently implemented; its text and source code are not copied.
- Noto Sans: local font copied from ArticulateArena, licensed under the SIL Open Font License; see `book/assets/fonts/OFL.txt`.

The cabinet controls use illustrative motion ranges. They are teaching diagrams, not a rigid-body physics simulator. The drawer's origin diagram uses the closed pose and matching frame orientations of this particular model; opposite offsets are not a universal URDF requirement. The earlier hinged-panel files remain in `book/assets/examples/` for future use, but are not part of the current introductory chapter.
